## Closure discipline and invariants

A new correction must name a row below, its demonstrated mechanism, a failing
behavioural check, and the evidence needed to close that defect. Reuse passing
evidence unless code, configuration, inputs or scope invalidate it. Keep source
tests, implementation commit, merge commit, deployment, runtime observation and
production acceptance separate. No percentage-complete estimate substitutes
for these gates. Do not re-open retired ordinary producers to manufacture trades.

Maintain account/host/position ownership, valid broker SL/TP, mandatory TP1, human
ownership, entry permissions, risk limits and research thresholds. No fabricated
money, quote timestamps, calendar semantics or successful activity. Missing
evidence remains Not Verifiable, and a observed failure remains Failed until a
correction has appropriate evidence. A passing normal cycle does not erase a
failed load/restart observation.

read-only worker execution without blocking management, preserving all
timestamps, missing-evidence states, account scope and notification policy?

needed. Behavioural parity, real HTTP wiring, worker isolation and bounded
failure checks precede any completion claim.

one reserved/coalesced watchdog slot in addition to the existing two dashboard

worker deadline and reads a coherent, read-only SQLite snapshot. That deadline
is a resource bound, not a new protection SLA or a guarantee of meeting the
verifier's existing 2-second HTTP deadline. A failed contract returns HTTP 503
with no fabricated healthy work list or observation timestamp.
