Setting `TICK_SPOOL_PATH` (e.g. `/data/tick`) on a sidecar is the owner's call; the recorder reports the mount's free bytes and UID problems itself once set.
- **Corrected 20-09-2026: a VOLUME is not what a sidecar needs in order to run the tick block. `TICK_SPOOL_PATH` is.** The path is the construction gate for the whole tick block, not only for the disk writer: the recorder is built only when it is set (`cpp-exec/src/main.cpp:191-193`), the tick firer starts inside `if (tickRecorder)` (`:259-263`), and the symbol workers, the strategies and the shadow books are built inside the same guard (`:264`); with no workers, `POST /config tickShadow` is ignored (`:1361`) and `GET /tick-status` answers `{"enabled":false,"reason":"TICK_SPOOL_PATH not set"}` (`:764`). `TickRecorder::start()` asks for nothing more than a creatable directory and an exclusive `flock` on `<dir>/.recorder.lock` (`cpp-exec/src/tick_recorder.cpp:311-361`), which a container-local path satisfies; and `main.cpp:200-206` KEEPS the recorder object even when `start()` fails, so the workers and the shadow are still built. The shadow itself reads the raw tap, not the file (`cpp-exec/src/tick_tap.hpp:80-81`, `tick_tap.cpp:17-21`), and a full spool stops only `writeRecord` (`tick_recorder.cpp:587-600`, `PAUSED_RESERVE`). **So the boundary is: a container-local spool path ⇒ the shadow and its evidence run (nothing survives a restart, and the recording is what a restart loses); a VOLUME is required only before ARMING**, because `disk_reserve_clear` (`agent/services/tick-readiness.js:80`) is one of the `PAUSE_CHECKS` (`agent/services/tick-permits.js:50`) that withhold live tick permits.
- The recorder's own budget is fixed in code and is not the volume's size: 64 MiB segments, a **2 GiB** spool cap, and a free-space reserve of the larger of **2 GiB** and 20 % of the mount (`cpp-exec/src/tick_recorder.hpp:178-181`). The "10GB volumes" in `plan.md` §10 and in TM-27's requirement title are the owner's reported Railway volumes as filed on 10-09-2026 — neither the spool cap nor the mount that was later measured (50 GB).
- The spool directory is created with a single-level `::mkdir` (`cpp-exec/src/tick_recorder.cpp:321-322`), not `mkdir -p`. `/data/tick` works on cpp-exec because `cpp-exec/entrypoint.sh:13,19` runs `mkdir -p` and `chown appuser` as root before dropping privileges; a service without that step would fail at the first missing parent.
