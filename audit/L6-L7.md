## A. ASSUMPTIONS

- `trades` is the only table holding realised outcomes; `trade_postmortems`, `risk_events`, `decision_log` and `action_log` are commentary on it, not sources of P&L. Falsified by any P&L aggregation reading another table — a directed search found none.
- Every closure funnels through `closeTradeRow` (`agent/db.js:878-895`) or the direct `UPDATE monitored_positions SET status='closed'` statements enumerated in D. Falsified by any other writer of `trades.status = 'closed'`.
- `label_regime` is snapshotted at order time from the regime row then current (`agent/loop.js:327-337`) and never updated afterwards, so attribution by regime reflects the regime as believed at entry — inheriting whatever staleness F-L1-09 describes, but not drifting after the fact.
- The only external network inputs to a decision are the cTrader feed, the ForexFactory calendar mirror, and the Anthropic API. Falsified by any other outbound `fetch` in a decision path — the searches in D list what was found.
- H1 (from L5.2 / F-L5-07) is in force for this pass.

**L7.3 — settled. The three most crowded assumptions, cheapest to degrade first.**

1. **"One position per symbol, and positions net."** Embodied in `agent/services/risk.js:604-617` (`duplicate_symbol`), `agent/services/risk.js:301-315` (`netExposure`), and contradicted by `agent/routes/actions.js:1154-1180` / `:1184-1211`. A counterparty does not need to attack this — it is self-inflicted — but the exposure it creates is cheap to exploit: the true position on a symbol can be several unlinked rows with independent bases and, per F-L5-03, at least one of them unprotected. Anyone who can move price against an unstopped add collects from a position the risk system does not know exists.
2. **"The stop lives at the broker, so we are protected between cycles."** Embodied in the whole keeper design (`agent/services/profit-keeper.js:26-27` states it explicitly) and in `cpp-exec/src/trail_engine.cpp`. It is true only while the amend succeeds, and every amend failure is silent (S17, S19) while `monitored_positions.current_sl` continues to describe the stop the bot *intended*. The cheapest degradation is a burst of volatility that makes stops momentarily unplaceable ("too close to market", the case the keeper's own comment anticipates at `profit-keeper.js:343-345`): the ratchet fails, nothing records it, and the position runs on a stale stop. Note the ratchets themselves cluster at conventional distances — `trailAtrMult: 2.5`, `spikeTrailAtrMult: 1`, `SL_ATR: 1.5`, `kDonchianSlAtr: 1.5` — so the stop locations are guessable from public volatility data.
3. **"A quiet feed means a quiet market."** Embodied in `agent/services/heartbeat.js:63-79` (a beat means the code ran, not that data arrived) and in `agent/services/fib-strategy.js:88-96` (a cache entry is fresh for one bar duration regardless of whether the fetch that filled it succeeded). Degrading a single data path — stalling the trendbar fetch for one symbol, or the spot stream — produces silence that is indistinguishable from no-setup (F-L3-02, F-L3-03) while positions stay open and the C++ fire path keeps acting on the last tick it saw (F-L2-05). The cheapest attack on this system is not a price attack; it is making one feed quiet.

## E. DATA REQUESTS (TIER-B)

- **DR-14** (L6.3, F-L6-08) — the one export that closes L6. Run all four; they must be from the same DB snapshot:
  ```sql
  -- (a) completeness first: how censored is the sample?
  SELECT COUNT(*) AS closed,
         SUM(CASE WHEN net_pnl IS NULL THEN 1 ELSE 0 END) AS null_pnl,
         SUM(CASE WHEN exit_price IS NULL THEN 1 ELSE 0 END) AS null_exit,
         SUM(CASE WHEN closed_at_ms IS NULL THEN 1 ELSE 0 END) AS null_closed_ms,
         SUM(CASE WHEN label_strategy IS NULL THEN 1 ELSE 0 END) AS null_strategy
  FROM trades WHERE status = 'closed';

  -- (b) hit rate + payoff + expectancy by REGIME
  SELECT label_regime, COUNT(*) AS n,
         AVG(CASE WHEN net_pnl > 0 THEN 1.0 ELSE 0.0 END) AS hit_rate,
         AVG(CASE WHEN net_pnl > 0 THEN net_pnl END) AS avg_win,
         AVG(CASE WHEN net_pnl < 0 THEN net_pnl END) AS avg_loss,
         AVG(net_pnl) AS expectancy
  FROM trades WHERE status='closed' AND net_pnl IS NOT NULL GROUP BY label_regime;

  -- (c) the same by INSTRUMENT (no route exposes this)
  SELECT symbol, COUNT(*) AS n,
         AVG(CASE WHEN net_pnl > 0 THEN 1.0 ELSE 0.0 END) AS hit_rate,
         AVG(CASE WHEN net_pnl > 0 THEN net_pnl END) AS avg_win,
         AVG(CASE WHEN net_pnl < 0 THEN net_pnl END) AS avg_loss,
         AVG(net_pnl) AS expectancy
  FROM trades WHERE status='closed' AND net_pnl IS NOT NULL GROUP BY symbol;

  -- (d) the rows H1 excludes, so they are excluded explicitly and not silently
  SELECT t.id, t.symbol, mp.scaled_out FROM trades t
    JOIN monitored_positions mp ON mp.trade_id = t.id
   WHERE mp.scaled_out = 1 OR t.close_reason LIKE '%revers%';
  ```
- **DR-15** (F-L6-02) — the local-close-without-broker-close population: the query in that finding's Detection column, plus a broker reconcile snapshot taken at the same moment.
- **DR-16** (F-L7-02) — calendar staleness in operation: `SELECT key, value FROM agent_state WHERE key IN ('news_calendar_fetched_ms');` sampled daily for a week, and one raw `ff_calendar_thisweek.json` body so the `date` field's timezone format can be pinned.
- **DR-17** (F-L7-03) — how often the LLM has closed a position: `SELECT id, symbol, close_reason, closed_at, net_pnl FROM trades WHERE status='closed' AND close_reason IS NOT NULL AND close_reason NOT LIKE 'closed at the broker%' AND close_reason NOT LIKE 'stale reconcile%' ORDER BY closed_at DESC LIMIT 200;` — the residue is position-manager reasons plus LLM `reasoning` strings, distinguishable by shape.
- **DR-18** (F-L7-04) — whether the login surface has been probed: Railway logs filtered to `[auth] 401` and `POST /auth/telegram/` over the retained window.
- **DR-19** (F-L6-06) — whether the daily-loss cap has ever been reachable: `SELECT DATE(closed_at) AS d, COUNT(*) AS n, SUM(CASE WHEN net_pnl IS NULL THEN 1 ELSE 0 END) AS nulls, COALESCE(SUM(net_pnl),0) AS summed FROM trades WHERE status='closed' GROUP BY d ORDER BY d DESC LIMIT 60;` — any day where `nulls > 0` is a day the cap under-counted.

## G. TOP 5 BY CAPITAL AT RISK

1. **F-L6-06 — the daily-loss caps sum NULLs to zero.** Not a measurement problem: the portfolio and per-account loss brakes are disabled for exactly the trades most likely to be losses. A day of broker-side stop-outs presents as flat and trading continues.
2. **F-L6-02 — a live position can be marked closed locally with no broker close.** `skipped` covers two cases where the position genuinely exists; from that moment nothing manages it and no sweep looks for it, because the local record says it is gone.
3. **F-L7-04 / F-L7-06 — one resettable credential path guards every money-moving route.** A 6-digit code with a non-durable attempt counter, plus a secret that F-L0-01 places in the browser bundle, both grant `position-double`, `position-reverse` and `close-all`.
4. **F-L7-03 — model output closes positions with no deterministic second gate.** The one input class with no provenance guarantee has direct authority over exits.
5. **F-L6-01 / F-L6-04 — the record used to size risk is incomplete, and the incompleteness biases edge upward.** Fourteen aggregation sites, including Kelly sizing and the auto-disarm breakers, read a sample censored against losers.
