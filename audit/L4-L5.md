# Audit Pass 2 — L4 Execution, L5 Trade Management

Repository: `ang-kl/bot-trade` @ `main`, `package.json` version 0.1.381.
Diagnosis only. L0 GIVEN not re-derived. Pass 1 findings referenced by ID.

---

## A. ASSUMPTIONS

- Every order, amend, close and cancel the Node agent performs passes through `agent/lib/exec-engine.js` (`placeOrder`, `amendPosition`, `closePosition`, `cancelOrder`). Falsified by any direct `wsPlaceOrder` / `wsClosePosition` import outside that module — a directed search found none outside `exec-engine.js` and the ws module itself.
- The only guarded submission point is `placeOrder`: `validateExecGuard` then `validateOrderBracket` (`exec-engine.js:191-195`). `amendPosition`, `closePosition` and `cancelOrder` are unguarded by construction on both engines.
- `monitored_positions.status='active'` is the set of positions the bot manages; `trades.status='open'` is the set it believes exists at the broker. Falsified by any manager reading a different predicate.
- One broker `positionId` maps to at most one `trades` row at a time; the dedup sweep at `agent/services/reconciler.js:297-` exists because that invariant has been violated in production.
- C++ `TrailEngine` and `VpoDispatcher` run only under the env gates read at `cpp-exec/src/main.cpp:173,185`. Both default false.

## D. LAYER VERDICT

**L4.1 — settled, as an enumeration of what is *not* modelled.** States actually represented: `trades.status ∈ {open, closed, cancelled, rejected}` (`agent/db.js:29`) and `pending_orders.status ∈ working/cancelled/expired/…` (`agent/services/pending-orders.js:217-219`, `agent/services/closed-market-limits.js:113`). Transitions handled: submit→fill (`loop.js:415-517`), submit→reject (`withRetry` rethrows on `order rejected`, `ctrader-ws.js:216`), working→cancelled (`pending-orders.js:217`), working→expired (`closed-market-limits.js:113`), open→closed-by-bot (`loop.js:872-892`), open→closed-at-broker (`reconciler.js:262-278`), open→orphan-swept (`reconciler.js:374-387`), broker-position→adopted (`reconciler.js:238-255`), local-desync→relinked (`reconciler.js:196-232`). **Unhandled:** partial fill (F-L4-05); cancel-replace as an atomic operation — there is none, only cancel then a fresh place on a later pass (`pending-orders.js:217` then `:234`), so the interval between them is unprotected and unrecorded; venue disconnect mid-flight (F-L4-01, and the sidecar's own `ExecEngine::request` failure surfaces as a thrown string with no state); restart mid-flight — no in-flight order record exists at all, so a process death between send and response is invisible to the next boot; and wrong-account routing (F-L4-02).

**L4.2 — PARTIAL.** Present: `orderSent`/`noRetry` prevents blind resubmission (`ctrader-ws.js:236-241`); a 3-minute ledger dedupe on the strategy path (`loop.js:389-402`); `duplicate_symbol` in the gate (`risk.js:604`); the sidecar's ARMED→FIRED CAS (`vpo_dispatcher.cpp:84-87`). Missing: any client order id on the wire; a record of an in-flight submission (F-L4-01); any dedupe on C02/C03/C06/C08 (F-L5-08); cross-strategy dedupe in the sidecar (F-L5-09). So: **a retry cannot double-fill on the path that retries, and can double-fill on the path that does not record.**

**L4.3 — settled.** Realised captured, assumed not modelled, fees deferred — F-L4-06.

**L4.4 — settled. DUAL-OWNED authority statement.** Under **`EXEC_ENGINE=js`**: `agent/lib/exec-engine.js:144-189` is the sole guard; `order_guard.cpp` is unreachable. Under **`EXEC_ENGINE=cpp`**: **both** run, JS first (`exec-engine.js:192-195`, before the HTTP hop) then C++ (`engine.cpp:302`), so the sidecar is the last line as designed. What C++ enforces that JS does not: nothing in kind — the checks are mirrors — but C++ enforces them against **every** caller of `ExecEngine::placeOrder`, including the VPO tier that never touches JS (F-L4-03), and it emits a rejection telemetry record with a classified reason code (`engine.cpp:303-308`), which JS does not. What JS enforces that C++ does not: the two bracket checks are **unconditional** in JS, whereas in C++ they are runtime-switchable atomics (`order_guard.hpp:51-52`, `POST /config`) — F-L4-07. Volume cap and halt are identical in both, with identical reason strings by design (`exec-engine.js:171-189`).

**L5.1 — settled per sub-item.**
- **a) REVERSE** — two-leg close-then-open (`actions.js:1195-1210`). Flat window = the whole of leg two: WS connect + app auth + account auth + `NEW_ORDER_REQ`, up to the 20 s `wsPlaceOrder` timeout (`ctrader-ws.js:232`). Leg-two rejection: HTTP 502 and the account stays flat, silently (F-L5-01, S13). Doubly-exposed window: none — the close precedes the open, so the exposure gap is one-sided.
- **b) ADD** — no weighted-average basis exists; no line to cite because there is none (F-L5-02). CAPITAL as the mission specifies.
- **c) ADD** — stop not re-derived; new leg naked; risk measured against neither basis (F-L5-03).
- **d) ADD** — no cap, before or after send (F-L5-03).
- **e) REDUCE** — residual **inherits** stop/target/time-stop by default. Via `executeBrokerAction` the inheritance is deliberate and the SL may be tightened in the same pass (`agent/loop.js:930-936`); `time_cap_at` is never re-derived on either path. Via the route, inheritance is accidental and the size record is left stale (F-L5-04).
- **f) REDUCE** — collapsed at final close. **No table.column holds tranche P&L** (F-L5-05). The columns that exist are `trades.gross_pnl`, `trades.net_pnl` — one pair per position row.
- **g) HEDGE vs NET** — the code assumes netting (`risk.js:604-617` refuses a second same-symbol position; `risk.js:301-315` sums offsetting legs) and the manual routes contradict it (F-L5-06). Venue side TIER-C, Q6.
- **h) ROLL** — no dated-instrument concept; the back-adjusted-series question is not answerable in-repo (F-L5-15) → DR-8 / OQ-8.
- **i) C09 AUTHORITY — resolves F-L0-07.** Under **`EXEC_ENGINE=js`**: `profit-keeper.js` and `position-manager.js` govern exclusively; `pushTrailConfig` returns false at `agent/lib/exec-engine.js:93` before any HTTP call, so `trail_engine.cpp` never receives a spec. Under **`EXEC_ENGINE=cpp` with `TRAIL_TICK_ENABLED` unset**: identical — the sidecar 503s `/trail-config` (`cpp-exec/src/main.cpp:391`) and `pushTrailConfig` swallows it (`exec-engine.js:98-100`). Under **`EXEC_ENGINE=cpp` with `TRAIL_TICK_ENABLED=true`**: **both govern, and neither is authoritative.** The delegation point is `agent/services/profit-keeper.js:350-352` → `agent/lib/exec-engine.js:92-101` → `POST /trail-config`; the policy (arm threshold, trail distance, spike tightening) is computed **only** in JS (`profit-keeper.js:139-178`) and handed over as `{trailDistance, peakPrice}`, so C++ owns no policy — but C++ owns the **execution** of the ratchet at tick resolution and keeps its own `peakPrice`/`lastSl` that override Node's snapshot when further along (`trail_engine.cpp:52-61`). The keeper's own amend path (`profit-keeper.js:335-346`) is never disabled when the sidecar is armed. Consequence: two writers, one DB record updated by only one of them (F-L5-10, S19).

**L5.2 — settled as the finding, and H1 fires.** Linking columns present: `monitored_positions.trade_id`, `trades.ctrader_position_id`, `trades.analysis_id`. Linking column for child events: **none** (F-L5-07). Per H1, L6 attribution is therefore **HALTED** for: (i) any position that was reversed — the two legs are unlinked rows, so entry-to-exit attribution across the reversal is not reconstructible; (ii) any position that was added to — sibling rows with independent bases; (iii) any position partially closed — the pre-reduction size and the banked tranche's P&L are destroyed, so neither R-multiple nor payoff can be computed for the trade as a whole. A defended absence is recorded in place of a number. Identity is retained only for the simple open→close case, and even there `reconciler.js:196-232` documents desync shapes (`reactivated_closed_row`, `created_missing_row`) that have occurred in production.

**L5.3 — settled per capability.**
- **C02** — no dedup key, no client order id; two signals in one tick both act (the route is stateless); a retry after timeout doubles the size (F-L5-08).
- **C03** — no dedup key. `scaled_out` is a single boolean flag (`agent/services/profit-keeper.js:265`, `agent/services/position-manager.js:194`), so it prevents a *second* scale-out but not two concurrent first ones; the route path sets no flag at all. A retry after timeout closes twice, which under-sizes rather than over-sizes — CORRECTNESS, not CAPITAL.
- **C06** — no dedup key; a retry re-closes (no-op or `POSITION_NOT_FOUND`) and then opens a **second** reversed leg. Double reversal is reachable (F-L5-08).
- **C08** — cancel is idempotent in effect (a second cancel errors harmlessly, `agent/routes/actions.js:984` swallows it); the *replace* half has no key, so a cancel followed by two places is reachable across passes.
- **C09** — no key; two writers (F-L5-10). Ratchet-only semantics bound the damage to an over-tight stop, not a widened one.

**L5.4 — settled.** Memory-only, lost on restart: the C++ `TrailEngine` peak/lastSl map and its `pendingSl` (`cpp-exec/src/trail_engine.cpp:44-66`); the sidecar's whole VPO arm state (`vpo_strategies.cpp` atomics); `lastPushedKey` in the Node process (`agent/lib/exec-engine.js:43`, whose failure mode is already documented in-place at `:45-50`). ## G. TOP 5 BY CAPITAL AT RISK

1. **F-L5-02 / F-L5-03 — ADD has no weighted basis, no stop, and no cap.** One route call places an unprotected position whose true cost basis the system cannot represent, and it can be called again immediately. Every R, every exposure sum and every P&L attribution for that symbol is wrong from that moment.
2. **F-L4-01 — the idempotency window reads a ledger the failing path never writes.** The one order outcome that is genuinely ambiguous is also the one that leaves no record, so the 3-minute guard is blind to exactly the case it was built for.
3. **F-L4-02 — position management addresses the globally selected account and host.** With two accounts enabled, closes and stop amends go to the wrong session, and `ctrader_is_live` also selects the host, so demo and live are one config key apart.
4. **F-L5-01 — REVERSE leaves the account flat on a leg-two rejection, silently, and the new leg carries no stop.** Both halves of the failure are unrecorded anywhere durable.
5. **F-L5-07 — no parent link for any child event, so H1 fires.** Reversals, adds and partial closes fragment into unlinked rows; the record used to size risk and measure edge is incomplete by construction, not by accident.
