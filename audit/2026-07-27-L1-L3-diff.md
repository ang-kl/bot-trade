## C. NEWLY FOUND in the 2026-07-27 pass, not present or not stated this way in the old pass

- **F-L1-01 (new) — VPO tier bypasses risk/news/duplicate-symbol/correlation gates entirely, per the C++ file's own header comment (`vpo_strategies.cpp:16-19`).** This is the new pass's #1 Top-5 finding and has no equivalent old finding — the 2026-07-26 audit's L1.5 dual-owned discussion (old audit section D, "L1.5") described the VPO tier as an independent *originating* decision-maker able to call `placeOrder` directly, but did not state, as a distinct findings-table row, that this bypasses the JS risk/news/duplicate-symbol/correlation layers specifically. Whether this is a fact newly documented in the code's comments since 2026-07-26, or a nuance the prior pass's synthesis simply did not surface as its own row, is not established by either report. **Flagged in the new audit itself as NOT independently cross-checked against `risk.js`'s call graph (DR-1)** — this is the single most important open item carried out of this diff: resolve DR-1 before treating this as confirmed rather than a comment-sourced claim.
- **F-L1-08 (new) — 3 of 11 registry strategies (`fib_618_fade`, `rsi_meanrev`, `va_breakout`) have no C++ port at all.** The old audit's L1.5 section named 7 dual-owned strategies plus "fib_618_fade is JS-only" as a one-line aside; the new pass elevates this to its own HYGIENE-severity finding and raises a live operator question (OQ-2/DR-3: what happens if `VPO_SYMBOLS` names one of the 3 unported keys — logged rejection or silent no-op). Not evidenced as answered by either pass.
- **F-L1-06 (new) — bar cache keyed only by `symbolId`, not `host`/`accountId`.** Not present in the old audit at all. Filed TIER-C (operator-context-dependent: matters only if the Node process ever runs more than one account's scans concurrently in the same process) — directly relevant to the in-flight multi-account migration plan (`docs/multi-account-migration-plan.md` survey, M1/M2 items) and should be cross-referenced there rather than treated as a standalone L1 defect today.
- **F-L1-04 (new) — VwapTrend stop-distance divergence from JS specifically scoped to "after a wick past the line," with EmaPullback explicitly cleared of the same suspicion.** The old audit's F-L1-03 bundled EmaPullback and VwapTrend together as both diverging on stop/target formula. The new pass's direct comment-reading of `vpo_strategies.cpp:94-111` vs `:274-296` found EmaPullback's own in-file comment claims exact-port status, and only VwapTrend's comment admits divergence (and only conditionally, when price has already wicked past the VWAP line). This narrows the old finding's scope — recommend the old F-L1-03's EmaPullback claim be treated as SUPERSEDED (narrower than stated) pending a direct side-by-side numeric check, since this diff did not itself re-derive the EmaPullback formula from first principles, only compared the two audits' comment-reading.
