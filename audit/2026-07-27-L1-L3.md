## A. ASSUMPTIONS

Each is falsifiable by the artefact named.

- The strategy registry is exactly the 11 keys in `agent/services/strategies.js:43-55`; nothing else can enter the scan. Falsified by any scan call site passing a `compute` not resolved through `STRATEGY_REGISTRY`.
- Every JS strategy is reached only via `pickBestSignal` (`agent/services/fib-strategy.js:440-462`), called once per timeframe at `agent/services/fib-strategy.js:522`, itself fed by the closed-bar slice computed at `fib-strategy.js:514-515`. Falsified by any other caller of a `compute*` export that does not pass through this slice.
- The C++ VPO tier can place live broker orders directly (bypassing the JS risk gate) when `VPO_ENABLED`/`VPO_SYMBOLS` arm a strategy, via `tryFire` → `placeOrder` per the header comment at `cpp-exec/src/vpo_strategies.cpp:16-19`. This claim is sourced to the C++ file's own comment; it was **not independently cross-checked against `agent/services/risk.js` in this pass** — see DATA REQUEST DR-1.
- Bars reaching every JS strategy are produced only by `decodeTrendbars` (`agent/lib/ctrader-ws.js:427-439`). Falsified by any other bar constructor feeding `compute*`.
- Test files under `agent/services/*.test.js` are evidence of intent only (K6); no test-file behavior is asserted as fact below.

## D. LAYER VERDICT

- **L1.1 (determinism):** settled with one live defect (F-L1-05 — wall-clock-conditioned closed-bar slice + mutable module cache, shared by all 11 strategies via the common caller).
- **L1.2 (parameter/sample size):** NOT EVIDENCED for 10 of 11 strategies; PARTIAL (comment only, no stored artefact) for `rsi2_reversion`. Blocked on DR-2.
- **L1.3 (regime dependency):** classification exists and is complete for all 11 keys (`regime-gate.js:49-61`); enforcement wiring into the live scan/signal path is NOT EVIDENCED from the files read in this pass (blocked on DR-4, extends into L2.4/F-L2-04).
- **L1.4 (look-ahead):** settled — the closed-bar guard is real, single-sited, and correctly shared by all 11 strategies through one caller, but its wall-clock-conditional nature is itself the residual defect (same as L1.1's F-L1-05, not a separate one).
- **L1.5 (dual-owned):** settled. 7 of 11 keys are ported to C++ (`vwap_trend, vp_value, ema_pullback, donchian_breakout, cup_handle, inv_cup_handle, fib_confluence, rsi2_reversion` — 8 listed, `cup_handle`/`inv_cup_handle` share one function pair, so 7 distinct strategy concepts); `fib_618_fade, rsi_meanrev, va_breakout` are JS-only (F-L1-08). None of the 7 ports are byte-identical to JS; every one diverges in at least entry timing (arm-before-touch is structural, not a bug) and at least 3 of 7 diverge additionally in a way that changes which trades fire or how they're sized (F-L1-02, F-L1-03, F-L1-04).
- **L2.1 (source/granularity/tz/gap):** settled. Source and granularity are clearly cited (`ctrader-ws.js` `TRENDBAR_PERIODS`); timezone is UTC epoch ms at one decode site; gap policy is confirmed absent (F-L2-01).
- **L2.2 (survivorship/restatement):** settled — confirmed absent (F-L2-02).
- **L2.3 (book depth):** H2 fires. No declared requirement exists; supplied depth is broker-determined and undocumented; the only consumer path (depth-capture.js → DB columns) is not read by any decision code. No depth-conditional finding is resolved or claimed elsewhere in this report.
- **L2.4 (staleness ceilings):** settled as a set, one bound per data type checked, with two structural gaps found: the regime bound fails open by default (F-L2-04) and the live tick feeding the VPO fire site has no bound at all (F-L2-05).
- **L3.1 (universe construction):** settled — static, JSON-blob-sourced, manually-pruned-only (F-L3-01).
- **L3.2 (liveness):** settled — dead vs. quiet is not separable at the instrument level; only account/session-level liveness is detected (F-L3-02).
- **L3.3 (silence decomposition):** the four cases are NOT fully separable. (b) scanner-never-ran and (d) empty-universe ARE separable from each other and from (a) via distinct log lines. (a) no-setup-found collides with the all-held-batch sub-case (F-L3-05). (c) per-symbol I/O failure is well-logged; (c′) a strategy-function exception is caught only by a generic, unlabeled outer catch (F-L3-03, the top silent-failure finding of this pass); (c″) corrupt watchlist JSON is not logged as a parse failure at all (F-L3-04).

## G. TOP 5 BY CAPITAL AT RISK

1. **F-L1-01 / S2 — VPO tier fires bypassing every JS safety gate (risk, news, duplicate-symbol, correlation), per the code's own admission.** If DR-1 confirms this, it is a live path from a single unfitted predicate directly to a broker fill with zero safety net — the highest-severity finding in this pass, pending independent verification.
2. **F-L3-03 / S1 — an uncaught strategy-function exception silently aborts the entire loop cycle, including monitoring of every open position, with no symbol/stage/phase named in the resulting log.** Distinct from #1 in kind: this is an OMISSION of risk management (positions go unwatched) rather than a bypass of it, and it requires no misconfiguration to trigger — any bug in any of the 11 strategy compute functions is sufficient.
3. **F-L2-05 — the C++ VPO fire site has no tick-staleness check at all, and can fire on a quote that predates a reconnect gap of up to 60 seconds.**
4. **F-L1-03 — the C++ Cup & Handle port drops the breakout-volume gate entirely (not proxied, just absent), arming trades the JS predicate would refuse outright.**
5. **F-L1-02 — the C++ Donchian port substitutes a volume proxy checked against the wrong bar, which can both admit trades JS would veto and miss trades JS would take.**

(F-L3-02 — dead-vs-quiet feed indistinguishability for a HELD position — and F-L2-04 — regime staleness fails open by default — were close calls for this list; both are real but conditional on a second event (a feed dying, or an operator having explicitly enabled the block) rather than firing on ordinary operation the way #1-#5 do.)
