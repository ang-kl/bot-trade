Executive Summary: Fixing poor or inconsistent AI agent outputs requires context engineering rather than padding prompts like an essay. By treating the context window as scarce working memory, bot-trade can curate high-signal tokens dynamically across seven context layers, prevent the four context failure modes (Poisoning, Distraction, Confusion, Clash), and enforce the four-step curation cycle (Write, Select, Compress, Isolate) across both coding-agent governance (CLAUDE.md) and runtime trading services (agent/services/).

Prompt Engineering vs Context Engineering 00:03:00

  • Prompt Engineering: How you word and structure instructions, examples, and constraints inside a static text block. Necessary, but insufficient when conversation and tool outputs snowball across turns.
  • Context Engineering: How you dynamically assemble everything the model sees at runtime right before every model call - the exact tools, retrieved facts, short-term state deltas, and output schemas needed for the immediate step.
  • The Scarce Working Memory Principle [00:01:41]: Larger context windows do not guarantee higher accuracy. Filling the window introduces stale text, irrelevant noise, and silent contradictions between sources.

Dual-Surface Application in bot-trade

  • Surface A - Coding & Review Governance (CLAUDE.md & Codex PR Reviews): Governs Plan-Loop CI/CD state machines, Order-Storm Refractory Gating specs, owner grounding rules, and serial ledger write-backs.
  • Surface B - Runtime Trading Services (agent/services/): Operates alongside deterministic modules (reconciler.js, trade-guard.js, profit-keeper.js, and C++ sidecar latches) to evaluate market context, hybrid 2R triggers, and operational boundaries.
  • Core Rule: Never ask an LLM to remember or calculate what deterministic code in reconciler.js or trade-guard.js can verify and inject as a compact fact.

Diagnostic Matrix: The Four Context Failure Modes 00:02:19 - 00:02:53

In multi-turn agents, accuracy drops when the context window fills with snowballed tool outputs and prior turns. Use these four failure modes to diagnose weaknesses in your prompt templates.

1. Poisoning 00:02:19

Video Definition: A hallucinated or erroneous fact enters the context window and gets reused repeatedly across subsequent turns.

Risk in bot-trade

If a runtime service in agent/services/ retains an earlier LLM inference about order fill status, margin availability, or trend regime in its rolling chat history, subsequent bars treat that unverified guess as broker truth. In coding workflows, an unverified assumption that a test or invariant passed gets repeated across turns.

Prompt Diagnostic & Fix

  • Strip all self-referential prose history regarding positions, fills, and balances.
  • Inject fresh, deterministic state strictly from reconciler.js broker receipts and C++ sidecar latches on every call.

2. Distraction 00:02:36

Video Definition: The model fixates on a massive history or essay-length prompt instead of formulating a fresh plan for the current step.

Risk in bot-trade

Passing hundreds of raw historical OHLCV bars, verbose execution logs, or entire multi-file PR histories dilutes attention away from the immediate decision boundary (such as hybrid 2R triggers or refractory cooldown gates).

Prompt Diagnostic & Fix

  • Audit the token ratio of static instructions + historical logs versus current-turn state data.
  • Apply Compress: keep at most the last 5 raw events and condense older history into a 3-line loss-aware state recap.

3. Confusion 00:02:36

Video Definition: Extra, unrelated details or tool schemas in the context window nudge the model toward an incorrect answer.

Risk in bot-trade

Mixing exploratory research instructions (bar-form research jobs or strategy brainstorming) with live execution guardrails (trade-guard.js and profit-keeper.js), or exposing MCP/API tool descriptions that are illegal in the current state-machine phase.

Prompt Diagnostic & Fix

  • Apply Isolate: separate your Reader, Scorer, and Writer prompts into distinct calls.
  • Dynamically filter the tools array so the model only sees functions permitted in its current state-machine phase.

4. Clash 00:02:45

Video Definition: Two sources of truth inside the context window silently disagree, and the model picks the wrong one.

Risk in bot-trade

Hard-coding numeric thresholds (USD notional exposure caps, mathematical expectancy floors, or order-storm refractory timers) inside prose prompts (CLAUDE.md or runtime prompt strings) while also encoding them in trade-guard.js or C++ sidecars. When code parameters change, prose prompts lag behind and create a silent clash.

Prompt Diagnostic & Fix

  • Remove duplicated numeric thresholds from prose system prompts.
  • Have trade-guard.js and profit-keeper.js compute the exact boolean/numeric gate state and pass that single authoritative object into Retrieved Facts.
